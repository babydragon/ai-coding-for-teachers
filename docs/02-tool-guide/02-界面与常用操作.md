# 02 · 界面与常用操作

> 这一章带你把 Reasonix 桌面版的界面逛一遍，搞懂每个区域是干什么的。
> 然后学会三种最基本的操作：开新会话、切换模式、管理项目。
> 界面描述以 Reasonix 桌面版 v1.19.x 为基准，不同小版本布局可能略有差异，但功能一致。

---

## 1. 界面的整体布局

Reasonix 桌面版打开后，界面大致分为这几个区域（自上而下、自左而右）：

```
┌──────────────────────────────────────────────────────────┐
│ ① 顶部：项目/会话标签栏          (+ 新建会话)             │
├──────────────┬───────────────────────────────────────────┤
│ ② 左侧栏     │  ③ 会话主区域                              │
│ 项目列表     │   ┌─────────────────────────────────┐     │
│ 文件浏览     │   │  ④ 对话记录（你与 AI 的往来）      │     │
│ 工具/技能    │   │   ...                            │     │
│              │   ├─────────────────────────────────┤     │
│              │   │  ⑤ 输入框 + 发送按钮 + 模式切换   │     │
├──────────────┴───────────────────────────────────────────┤
│ ⑥ 底部状态栏：模型 / 费用 / 上下文用量 等                 │
└──────────────────────────────────────────────────────────┘
```

## 2. 各区域详解

### ① 顶部标签栏 —— 多个任务同时开

- 可以同时开好几个「会话标签」，就像浏览器开多个标签页。
- 每个标签 = 一个独立的对话任务，互不干扰。
- 点「+」新建会话；点标签切换；点标签上的 ✕ 关闭。

> 💡 建议：给不同任务各开一个会话（比如「做乘法游戏」「做语文生字卡」各一个），避免内容混在一起把 AI 搞糊涂。

### ② 左侧栏 —— 项目与文件

- **项目（Projects）**：你的工作文件夹列表。做学生工具前，先为它建一个专门文件夹（项目）。
- **文件（Files）**：当前项目里的文件树，点开能看到 AI 生成/修改了哪些文件。
- **技能（Skills）**：可用的「工作方法说明书」，点击可让 AI 按某个规范干活。

> 老师建议：**一个项目 = 一个学生工具**。比如 `D:\学生工具\乘法游戏` 一个项目、`D:\学生工具\拼音卡片` 另一个项目。文件井井有条，AI 也不会串。

### ③ 会话主区域 —— 你与 AI 的对话现场

这里滚动显示你和 AI 的全部往来：你的指令、AI 的回答、AI 调用工具的过程、AI 写的文件内容、AI 运行程序的结果……全部有记录，随时可以回看。

> 第一次用时你可能会惊讶：「AI 在干什么？怎么那么多步骤？」
> 别慌，这正是第二章讲的「计划→执行→观察」循环，你在围观 AI 干活的过程，而不是只看结论。

### ④ 输入框与发送 —— 下指令的地方

- 在输入框里用中文写你的需求，按回车或点发送。
- 指令可以很随意：「做一个乘法小游戏」「帮我看看这个文件哪里有问题」都可以。
- 按 `Shift+Enter` 可以换行写多段要求。

### ⑤ 模式切换 —— 决定 AI 的「自主程度」

这是 Reasonix 最重要、也最该理解的控件，通常是一个下拉或按钮组：

| 模式 | 含义 | 老师怎么用 |
| --- | --- | --- |
| **Ask（询问）** | AI 每次要动文件/运行命令前，都先问「可以吗？」，你点「允许」才继续 | 刚开始用、或不放心时 |
| **Auto（自动）** | 常规操作自动放行，只对危险操作（删文件等）询问 | 日常推荐 |
| **YOLO（全自动）** | 不询问，AI 放手干 | 信任之后再用 |

> ⚠️ 新手第一次做工具，建议保持 **Ask 或 Auto**，亲眼确认 AI 的每一步都合理。等你熟悉了「AI 会在项目文件夹里建文件」这件事，再考虑 YOLO。

另外还有 **Plan（计划模式）**：AI 先只做计划、不实际动手，等你确认计划后再执行。适合「让它先想想怎么做、给你看方案」的场景。

### ⑥ 底部状态栏 —— 实时仪表盘

显示当前状态，常用指标（在设置里可以勾选显示哪些）：

| 指标 | 含义 |
| --- | --- |
| `model` | 当前用的模型 |
| `workspace` | 当前工作目录 |
| `session_tokens` / `turn_tokens` | 本次会话/这一轮用的 Token 量 |
| `context` | 上下文用量（接近上限时 AI 会压缩纪要） |
| `turn_cost` / `cost` / `balance` | 这轮花费 / 总花费 / 账户余额 |
| `git_branch` | 当前版本分支（了解即可） |
| `cache` | 缓存命中（省钱的指标，了解即可） |

> 💡 老师可以随时瞄一眼余额和花费，心里有数；做一个小工具通常很便宜。

## 3. 项目与会话：两个最基础的概念

先分清两个词，后面所有操作都围绕它们：

| | 项目（Project） | 会话（Session） |
| --- | --- | --- |
| 是什么 | 一个文件夹 | 一次对话 |
| 装什么 | 你的工具文件（index.html 等）+ 规矩（AGENTS.md） | AI 的「工作记忆」（你说了什么、它做了什么） |
| 生命周期 | 长期存在，关软件、重启都不消失 | 自动保存，但每次新建都是一张干净的「工作台」 |
| 教学类比 | 一个班级的档案柜 | 批作业时摊开在桌上的那叠卷子 |

### 3.1 什么时候该新建项目？

需要「新开一摊事」，并且希望它和其他东西完全分开时：

| 场景 | 例子 |
| --- | --- |
| 做一个全新的工具 | 要做「乘法游戏」→ 新建项目文件夹 |
| 想换一套规矩 | 低年级的项目和中学生的项目要求不同，各建各的 |
| 想独立管理、不互相影响 | 每个学生工具一个项目，文件不混在一起 |

> 💡 记住：**一个项目 = 一个学生工具**（或一个系列）。规矩（AGENTS.md）也是按项目放的。

### 3.2 什么时候该新开一个会话？

在同一个项目里，开始一件「新的事」，或想让 AI 忘掉旧事重来时：

| 场景 | 例子 |
| --- | --- |
| 同一个项目里做新任务 | 乘法游戏做完了，又要在同一文件夹里做「除法游戏」 |
| 对话太长，AI 开始「健忘」 | 上下文快满，AI 忘了最开始的要求，回答变差 |
| 改了 AGENTS.md | 规矩变了必须新开会话才生效（见第四部分） |
| 想把之前聊乱的重新来一遍 | 从干净状态重新开始 |

### 3.3 什么时候该复用（继续）旧会话？

接着上次的话头继续干时：

| 场景 | 例子 |
| --- | --- |
| 同一个任务还没做完 | 昨天让 AI 做乘法游戏做到一半，今天继续 |
| 修改现有工具 | 「把配色换成蓝色」——AI 记得这个文件的全部细节 |
| 连续调整 | 改完一版还要接着改下一版 |

> 教学类比：
> - **开新项目 = 拿一个新的档案柜**；
> - **开新会话 = 把旧卷子收起来，摊开新卷子**；
> - **复用会话 = 接着批这叠卷子，别换**。

### 3.4 常见疑问

- **Q：会话聊乱了，文件会乱吗？** 不会。文件在项目文件夹里，会话只是「工作记忆」。新开会话，文件都还在。
- **Q：新开会话后 AI 不认识我的文件了？** 它依然能看到项目文件夹里的所有文件，只是忘了「上次对话说了什么」，重新说一句「继续改那个乘法游戏」即可。

## 4. 三个最基本的操作

### 操作一：新建项目并开始第一个会话

👉 动手做：

1. 顶部点「+ 新建会话」。
2. 选择（或新建）一个项目文件夹，例如：`D:\学生工具\乘法小游戏`。
3. 在输入框输入你的第一个指令，例如：

   > **「在这个项目里，做一个给小学三年级学生用的竖式乘法练习网页，要带动画演示怎么对齐、怎么写进位。」**

4. 发送，然后看 AI 开始干活。

### 操作二：切换模型（换大脑）

👉 动手做：

1. 点底部状态栏的 `model` 区域（或设置里的模型页）。
2. 选择另一个模型，例如从 `deepseek-v4-flash` 切到 `deepseek-v4-pro`。
3. 当前会话之后的对话就用新模型了。

> 💡 简单任务用便宜的 flash 模型，复杂任务临时切 pro，能省不少钱。

### 操作三：中途插话 / 修改要求

AI 干活干到一半，你想改要求？直接输入：

> **「等一下，配色换成浅蓝色系，按钮再大一点。」**

AI 会停下当前工作，按新要求调整。你随时是「甲方」，AI 随时听你改。

## 5. 会话的保存与续聊

- Reasonix 自动保存每个会话。关掉软件再打开，历史会话都还在。
- 顶部标签栏或会话列表里点开旧会话，可以继续聊（AI 记得之前干了什么）。
- 换机器/换人时，把整个项目文件夹拷贝走，AGENTS.md 和会话记录一起带走。

## 6. 如何判断 AI 的申请：只读？越界？看不懂？

AI 动手前（尤其在 Ask/Auto 模式下）会弹出申请：**要做什么、动哪个文件、跑什么命令**。老师最大的困惑是「我看不懂，怎么判断？」，这一节给你一套口诀。

### 6.1 第一问：是「只读」还是「要改动」？

| 申请内容 | 类型 | 判断 |
| --- | --- | --- |
| 列目录、找文件、读文件内容、查看信息 | 只读 | 放心放行，不会弄坏任何东西 |
| 创建/修改文件（如 write_file、edit_file） | 写 | 看第二问：改哪个文件 |
| 运行命令（bash、python 等） | 执行 | 看第三问：跑的是什么 |
| 删除、移动、重命名文件 | 高危 | 先停下来问清楚：为什么动这个文件 |

### 6.2 第二问：要动的文件在「工作范围」内吗？

Reasonix 只应该动**当前项目文件夹**里的文件。判断方法：看申请里显示的路径开头。

- ✅ 安全：路径以你的项目文件夹开头，如 `D:\学生工具\乘法游戏\index.html`
- ⚠️ 警惕：路径在项目文件夹之外，如 `C:\Windows\...`、`D:\其他\xxx`、桌面上的无关文件
- ⚠️ 警惕：出现 `..\`（返回上级目录）、`C:\`（系统盘根目录）等写法

> 教学类比：只允许它动「这个班的档案柜」，伸手去别的班柜子就要拦下来问。

### 6.3 第三问：运行的命令看得懂吗？

这是最常见、也最容易踩坑的地方。大模型为了图省事，经常把一堆操作塞进**一条**命令里，例如：

```
python3 -c "..." | bash -c "..." && python3 game.py > result.txt
```

一条命令里：生成代码 + 执行 + 管道 + 重定向 + 再跑一次，全混在一起。**这种命令，哪怕是程序员也要读半天。**

判断规则很简单：

| 情况 | 怎么办 |
| --- | --- |
| 命令简单、作用明确（如「运行项目里的测试」） | 可放行 |
| 命令很复杂、嵌套、看不懂 | **选择「拒绝 / 暂不执行」**，然后让 AI：「把这条命令拆开，一步一步解释每步在干什么」 |
| 解释后还是不明白，或觉得没必要 | 直接要求：「别用嵌套命令，分几步做，每一步先问我」 |

> ⚠️ 关键：**看不懂就拒绝，是安全的，不是不配合。** 好的 AI 会耐心拆开解释，而不是闹脾气；解释后你仍然有最终决定权。
>
> 另外注意：即使在 Auto（自动）模式下，Reasonix 遇到它自己都无法判断的操作（比如极其复杂的嵌套命令）也会停下来请你人工确认——**这不是出故障，而是安全保护**，说明这一步确实值得你亲自看一眼。

### 6.4 最省心的办法：把风险挡在源头

与其每次判断，不如让 AI 少干「越界的事」：

1. **每个项目一个干净文件夹**：AI 只在这个文件夹里干活，路径检查基本不会出问题。
2. **把规矩写进 AGENTS.md**：直接写「只允许修改当前项目文件夹内的文件；禁止删除文件；运行命令前先解释要干什么」——AI 就会主动先解释，省得你盯。
3. **重要文件先备份**：动手大改前，把项目文件夹复制一份。

这样大部分申请都变成「只读 + 项目内修改」，需要你警惕的就很少了。

## 7. 重要安全习惯（老师必看）

1. **先看后放行**：AI 要动文件时，按第 6 节的「三问口诀」判断（只读？在不在项目里？命令看得懂吗？）。
2. **重要文件先备份**：可以把项目文件夹复制一份再让 AI 大改。
3. **不要把 API Key 发出去**：任何时候都不要把 Key 截图、发群。
4. **学生工具发布前自己先玩一遍**：AI 做的东西，先自己点一遍确认没问题，再给学生用（第四部分 AGENTS.md 会把这些习惯写进规矩，让 AI 替你守）。
