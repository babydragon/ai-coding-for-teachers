# 02 · Agent 编码原理：看 Reasonix 是怎么一步步干完活的

> 上一章我们认识了「Agent」这个名词。这一章用 Reasonix 的真实工作过程，拆开给你看：
> **大模型 + 工具调用 + 循环反馈**，是怎么组合成一个能干活的 AI 助手的。
> 看懂这一章，你就理解了「为什么 AI 能自己写代码」，以后也能判断 AI 干活靠不靠谱。

---

## 1. 一个真实例子：从你说一句话开始

假设你对 Reasonix 说：

> 「做一个竖式乘法小游戏，给三年级学生用，要带动画演示进位。」

这句话进入 Reasonix 后，会发生这样一串事（这也是本指南第三部分要带你亲手做的）：

```
你说：做一个竖式乘法小游戏（带动画、演示进位）
 │
 ├─① 理解任务    大模型把这句话拆成：做网页工具 / 教三年级 / 要有动画
 ├─② 补充规矩    Reasonix 自动读取项目里的 AGENTS.md（如果有），把规矩加进任务
 ├─③ 制定计划    Agent 在脑子里（或显示给你看）列出步骤
 ├─④ 动手干活    调用工具：write_file 创建 index.html、edit_file 修改……
 ├─⑤ 检查结果    调用工具：运行程序、打开页面，看效果对不对
 ├─⑥ 发现问题    比如「进位没显示」→ 回到③修改
 ├─⑦ 反复循环    直到自己觉得符合要求（或让你验收）
 └─⑧ 交作业      告诉你：做好了，文件在哪，怎么打开
```

**重点**：第④~⑥步不是「AI 一口气吐出一大段代码」就完事了，而是 **「写一点 → 检查 → 发现问题 → 修改」的循环**，和你备课、改教案的过程一模一样。

---

## 2. 拆解原理：四个核心部件

### 2.1 大脑：大模型（LLM）

- 负责「想」：理解你说的话、决定下一步做什么、写代码、写说明。
- Reasonix 不内置大脑，而是「接入」大模型的 API（如 DeepSeek、GLM 等）。换模型 = 换大脑。

### 2.2 手：工具调用（Tools）

- 负责「做」：读文件、写文件、运行命令、搜代码、抓网页……
- 大模型自己不能碰你的电脑，它只能「说」——但 Agent 框架（Reasonix）提供了一套工具，让大模型可以**申请调用**，由 Reasonix 在本机执行，再把结果反馈给大模型。

> 类比：大模型是「指挥」，工具是「执行的人」。指挥说「把文件第 20 行改成 XXX」，Reasonix 替它动手，然后把改完的结果告诉指挥。

### 2.3 循环：计划 → 执行 → 观察 → 再计划

- 这是 Agent 区别于「聊天机器人」的本质。
- 聊天机器人：你问一句，它答一句，结束。
- Agent：**任务没有完成信号之前，它会一直循环**——做一步、看一眼结果、决定下一步。

```
┌────────────┐    ┌────────────┐    ┌────────────┐
│  计划       │ →  │  执行       │ →  │  观察结果   │
│ (LLM 想)   │    │ (调用工具)  │    │ (看工具反馈)│
└────────────┘    └────────────┘    └────────────┘
       ↑                                  │
       └──────── 没完成就再来一次 ←────────┘
```

### 2.4 记忆：上下文（Context）

- Agent 把「你说的话 + 项目规矩（AGENTS.md）+ 它之前干过的事 + 工具返回的结果」都放在上下文里，作为它继续思考的依据。
- 内容太长时，Reasonix 会自动「压缩纪要」（compact），保证对话能继续、且不爆掉模型的上限。

## 3. 关键时刻：工具审批（Ask / Auto / YOLO）

Reasonix 要动你电脑上的文件、运行命令时，**默认会先问你同不同意**（这很重要——AI 不能未经允许乱动你的文件）。

Reasonix 有三种「放行模式」，在界面上可以切换：

| 模式 | 意思 | 适合场景 |
| --- | --- | --- |
| **Ask（询问）** | 每次调用工具前都问你「允许吗？」 | 新手、动重要文件时，最安全 |
| **Auto（自动）** | 常规操作自动放行，只对敏感操作（如删除文件）才问 | 日常使用推荐 |
| **YOLO（全自动）** | 所有操作都不问，直接干 | 信任 AI、任务明确时用，风险自负 |

> 💡 教学类比：Ask=每次请假都找你签字；Auto=班干部按班规处理日常事务，大事才汇报；YOLO=完全放手，出事自己兜着。
>
> 老师第一次用，建议先用 **Ask** 或 **Auto**，亲眼看看 AI 每一步干了什么，建立信任感后再考虑放开。

## 4. 再拆一个真实场景：我在写这份文档时干了什么

以「编写这份文档」这个任务为例，看看 Agent（也就是现在的我）实际的工作轨迹（已简化）：

| 步骤 | Agent 做了什么 | 用的工具/能力 |
| --- | --- | --- |
| 1. 探路 | 先看看项目文件夹里有什么、有没有旧文档 | `ls`（列目录） |
| 2. 查配置 | 查看 Reasonix 的配置文件，确认工具的真实功能、界面名词，避免文档写错 | 读取 Reasonix 配置文件 |
| 3. 确认需求 | 遇到「文档怎么组织」「示例选什么知识点」这类该由你决定的点，主动问你 | 提问功能（Ask） |
| 4. 规划 | 把大任务拆成 13 个步骤，列成清单，逐步推进 | 任务清单（todo） |
| 5. 写作 | 一章一章地创建 Markdown 文件 | `write_file`（写文件） |
| 6. 自查 | 每完成一步，检查写得对不对、链接通不通 | 检查工具 + 阅读自己写的内容 |
| 7. 汇报 | 最后把成果、文件位置、注意事项告诉你 | 总结汇报 |

**你注意到的细节**：Agent 不是一次性把所有内容吐出来，而是「先看 → 再想 → 再写 → 再检查」，并且**遇到真正需要你拍板的决策，会停下来问你**，而不是自作主张。这正是「Agent 帮你干活」和「AI 瞎写一气」的区别。

---

## 5. 为什么需要 AGENTS.md：给循环加一个「班规」

回到第 2 节的循环图。你发现没有，Agent 每转一圈，都要重新面对一个问题：

> 「这个项目的规矩是什么？学生用的工具应该做成什么样？」

如果每次都靠你口头强调，一是累，二是容易忘。所以 Reasonix 支持一个机制：**项目根目录放一个 AGENTS.md，每次会话开始，Agent 自动把它读进上下文**。

效果（教学类比）：

- 没有 AGENTS.md：每次来一个代课老师（新会话），都要从头交代一遍班规，还经常漏。
- 有 AGENTS.md：班规贴在墙上，谁来都先看，按规矩办。

AGENTS.md 写什么、怎么写、有哪些模板 → 第四、五部分详述。

---

## 6. 这一章的要点回顾

1. Agent = 大模型（大脑） + 工具（手） + 循环（计划→执行→观察）+ 上下文（记忆）。
2. 工具调用前会征求你的同意（Ask / Auto / YOLO 三档）。
3. Agent 会**检查自己的成果**并反复修改，而不是一次成型。
4. 遇到「该由你决定」的事，靠谱的 Agent 会问你，而不是替你决定。
5. AGENTS.md 是给整个循环「定规矩」的关键文件。
